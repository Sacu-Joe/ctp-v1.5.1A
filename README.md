# 校园任务平台 · HTML 版

桌面版「校园任务平台」的 **HTML5 版本**，纯网页实现、**无需编译、零构建、可完全离线运行**；
后续用 **Capacitor（推荐）或 HBuilderX 套壳打包成 Android APK**。数据口径、界面与交互均与桌面版一致。

当前进度：**五大模块（日程 / 课程表 / 考试成绩 / 活动 / 课堂笔记）+ 应用外壳 + 首页已全部完成**，
并通过数据层 149 项自检与界面端到端自检，无「开发中」占位。

---

## 1. 现在能用什么

- **应用外壳**：左侧约占 1/7 的纵向导航（5 个模块，PNG 图标）、顶部学校切换与日期、底部全局设置；
  点左上「校园任务平台」品牌区回首页。
- **多学校管理**：顶栏学校胶囊 → 新建学校（输入校名）/ 切换学校 / 删除学校（至少保留一所）。
  不同学校的课表、活动、笔记、图片**按校名完全隔离**；删除学校会级联删除其全部数据。
- **首页（打开软件的第一个页面）**：
  - 「今日课程」积木：显示当天**接下来最多 5 节**课的名称、上下课钟点（含节次）、地点，
    积木大小颜色统一、**透明度 75%**、积木式堆叠，点击进入课程表；
  - 「今日活动」卡片：显示当天全部活动（名称、时间、地点、类型标签），卡片式堆叠；
  - 「最近考试」简卡（右列活动下方，**无成绩时不显示**）：显示日期最新一场考试的总得分率、
    总分 / 总满分、班级 / 年级名次、科目数与平均 / 最高 / 最低科目，点击进入考试成绩；
  - 进入首页会自动把已结束的活动归档（历史仍保留，可在后续「活动」模块导出）。
- **课程表（教学周课表）**：
  - 单一网格呈现周一~周日 × 节次；**连堂课沿网格线跨多格**，课程块严格在格子内，不跨格错位；
  - 区分**单周 / 双周 / 全周**，顶部可 ◀▶ 切换周次、一键「回到本周」，并显示单/双周徽标，当天列高亮；
  - **单击空白格**按该天该节新增课程；**双击课程块**编辑或删除（单击不会误触编辑）；
  - 课程字段：课程名 / 上课地点 / 任课老师（字符串），星期、起止节次、起止周次（数字）、单双周；
    含节次与周次范围、先后顺序校验；
  - 课表设置（齿轮图标）：总教学周数、每天节次数、开学日期；课程块颜色按课程名稳定取色。
- **日程（数据全局，不区分学校）**：
  - 左侧**月历**：◀▶ 切换月份、点选日期；有日程的日期下方显示青绿圆点，今天描边、选中日期实心高亮；
  - 右侧**当日待办**：未完成在前、按开始时间升序（全天排最后）、已完成置底加删除线；
    勾选框可标记完成，**双击条目**编辑，卡片上可删除；
  - 新建 / 编辑：日程内容、日期、全天开关、起止时间、备注；含必填与「结束不早于开始」校验；
  - **到点弹窗提醒**：工具条内「到点弹窗提醒」开关（与「全局设置」中同一开关，双向同步）；
    开启后，应用在前台打开时每 20 秒检查一次，到达日程开始时间即聚合弹窗提醒，且只提醒一次。
    （手机后台 / 锁屏提醒将在套壳成 App 后改用本地通知。）
- **活动（数据按学校保存）**：
  - 三种视图可一键切换，默认**卡片墙**：**卡片墙**（3 列卡片，左侧 5px 类型色条，含名称 / 类型标签 /
    日期星期 / 时间或全天 / 地点 / 组织者 / 备注，**双击卡片**编辑或删除）、**列表**（类型 / 名称 /
    日期时间 / 地点 / 组织者横向行）、**日历**（上方自绘月历，有活动的日期加粗青绿标记；下方列出选中日活动）；
  - 新建 / 编辑：名称、日期、类型（社团 / 比赛 / 讲座 / 志愿实践 / 文体活动 / 其他）、全天开关、
    起止时间、地点、组织者、备注；含必填与「结束不早于开始」校验；编辑弹窗内可删除（二次确认）；
  - **已结束活动自动归档**：进入模块或增删改后，按当前时间把已过结束时间（当天）或更早日期的活动
    自动移入历史并从界面删除；**历史记录**弹窗只读查看，可一键**导出为 txt**（活动无到点提醒、无参与状态）。
- **课堂笔记（数据按学校保存）**：
  - 左栏：关键词**搜索**（标题 / 科目 / 正文实时过滤）、**按科目筛选**（全部科目 / 课程名 / 笔记自定义科目）、
    笔记列表（按修改时间倒序，显示标题与「科目 · 月/日 时:分」）；
  - 右栏：标题、科目（可手动输入新科目，并带课程名联想）、**富文本编辑器**——加粗 / 斜体 / 下划线、
    6 档字号、文字颜色、左中右对齐、无序列表、**插入图片**（图片自动缩放到宽 600，GIF 保留原文件）；
  - 编辑后约 1.2 秒**自动保存**，也可手动保存；切换笔记 / 模块前静默保存；删除需二次确认；
    图片以 Blob 入库、正文用 `asset:<id>` 占位，删除笔记后自动清理不再被引用的图片。
- **考试成绩（数据按学校保存）**：
  - **按考试 / 按科目双维度**，顶部一键切换。
  - **按考试看**：考试卡片墙（最新在前，类型标签：月考 / 期中 / 期末 / 模拟考 / 其他），
    显示总得分率（大字、按分值分级配色）、总分 / 总满分、班级 / 年级名次、科目数、平均与最高最低科目；
    **单击卡片**进只读详情——总得分率 / 平均 / 总分排名 / 最高最低统计、**各科得分率横条**、
    单科成绩与单科排名表，详情内可进入录入 / 编辑。
  - **按科目看**：每个科目一张卡（最新得分率、最新分数、平均、最高 / 最低、相比上次 ▲▼）；
    **单击卡片**看该科历次成绩表、**得分率趋势折线**（按满分折算，满分不同也可比较）与
    **单科班排 / 年排趋势折线**（名次越小越靠上，缺值断线）。图表均为内置 SVG 自绘，零外部依赖。
  - **新建 / 编辑考试**（加宽弹窗）：考试名称、日期、类型、学期 / 学年分组、班级名次、年级名次、备注，
    加一整张**科目成绩表**（科目、得分、满分、单科班排、单科年排，可任意增删行）；
    各科**满分可以不同**，得分按「得分 / 满分」录入、**自动折算得分率**，得分留空表示该科暂未出分；
    底部随输入**实时统计**已填科数、总分 / 总满分、总得分率、平均、最高 / 最低；
    含必填、满分 > 0、得分 0~满分、科目不重复等校验；删除考试二次确认并**级联删除其全部成绩**。
  - **教务网站自动导入（仅预留接口，本版无界面入口）**：数据层提供固定数据格式
    `campus-platform.scores.v1`、模板 `Store.scoreTemplate()`、数据源适配器注册
    `Store.registerScoreProvider()` 与幂等导入 `Store.importScores()`（同校 + 同名 + 同日期视为同一场，覆盖更新）；
    将来源对接具体教务网站时，只需新增一个 `{id,name,fetch,parse}` 适配器，无需改动界面。
- **全局设置**：日程到点提醒开关、**导出备份 / 导入备份 / 清空所有数据**（备份含考试与成绩）。

## 2. 如何运行

- **方式一（最简单）**：双击 `index.html`，用 Microsoft Edge 或 Chrome 打开即可使用，数据保存在本机。
- **方式二（推荐，最稳妥）**：用任意静态服务器托管本文件夹后访问 `index.html`
  （例如 VS Code 的 Live Server 插件）。个别浏览器对 `file://` 下的 IndexedDB 有限制，
  若出现数据不保存等现象，请改用本方式；打包成 APK 后不存在该问题。

> 注：首次打开会自动创建一所「我的学校」（20 周、每天 10 节、开学日为本周一，作息采用方案一：
> 第 1 节 08:00–08:45，……，第 10 节 19:55–20:40），日程提醒默认开启。

## 3. 数据存在哪里、会不会丢

- 所有数据保存在浏览器 / WebView 的 **IndexedDB**（库名 `CampusPlatformDB`），持久化存储，
  **关闭页面、重启电脑 / 手机都不会丢失**。
- 但它位于应用沙盒内，**卸载 App、清除应用数据会一并删除**。请定期在「全局设置 → 导出备份」
  生成一个 JSON 文件妥善保存；换设备 / 重装后用「导入备份」完整恢复（含笔记图片）。

│     ├─ schedule.js       日程（月历 / 当日待办 / 增删改 / 完成 / 提醒开关）
│     ├─ activity.js       活动（卡片墙 / 列表 / 日历三视图、增删改、自动归档、历史 txt 导出）
│     ├─ notes.js          课堂笔记（搜索 / 科目筛选 / 富文本 / 插图 / 自动保存）

脚本在 `index.html` 中按固定顺序以普通 `<script>` 加载（非 ES Module）：
`dexie.min.js → utils.js → db.js → store.js → app.js → views/home.js → views/timetable.js → views/schedule.js → views/activity.js → views/notes.js → views/scores.js`。

## 5. 数据模型（9 张表）

| 表 | 主键 / 索引 | 说明 |
|---|---|---|
| `kv` | key | 全局键值：当前学校、日程提醒开关等 |
| `schools` | name | 学校：总周数、每天节次、开学日、作息钟点 |
| `courses` | id, school, day, [school+day] | 课程（含单双周、连堂节次、周次范围） |
| `schedules` | id, date, done | 日程（**全局，不分学校**） |
| `activities` | id, school, date, archived, [school+archived] | 活动，`archived=1` 为已归档历史 |
| `exams` | id, school, date, type, term, [school+date] | 考试（名称 / 日期 / 类型 / 学期 / 总分班排年排 / 备注） |
| `scores` | id, school, examId, subject, [school+examId], [school+subject] | 单科成绩（得分 / 满分 / 单科班排年排） |
| `notes` | id, school, subject, modified | 课堂笔记（富文本 HTML + 插图引用） |
| `assets` | id, school | 笔记图片的 Blob |

「分学校目录」在 Web 版改为：除日程外每条业务记录带 `school` 字段，查询按当前学校过滤。
笔记图片以 **Blob 存入 IndexedDB**，富文本中用 `asset:<id>` 占位，显示时替换为临时 `blob:` URL；
备份 JSON 中图片以 base64 dataURL 内联。

关键字段：

- 课程 `{ id, school, name, place, teacher, day(1-7), startPeriod, endPeriod, startWeek, endWeek, weekType('all'|'odd'|'even') }`
- 日程 `{ id, title, date('yyyy-MM-dd'), start, end('HH:mm'，空串=全天), note, done, reminded }`
- 活动 `{ id, school, name, date, start, end, place, organizer, type, note, archived(0|1), archivedAt }`
- 笔记 `{ id, school, title, subject, html, created, modified(ISO) }`
- 考试 `{ id, school, name, date('yyyy-MM-dd'), type('月考'|'期中'|'期末'|'模拟考'|'其他'), term, classRank(int|null), gradeRank(int|null), note, createdAt }`
- 单科成绩 `{ id, school, examId, subject, score(number|null，空=未出分), maxScore(>0，默认100), classRank(int|null), gradeRank(int|null) }`
- 学校 `{ name, totalWeeks, periodsPerDay, firstDate, bells:[{s,e}], createdAt }`

## 7. 后续工作

1. 用 **Capacitor**（推荐）或 HBuilderX 套壳打包 Android APK。
2. **日程后台提醒**：当前到点提醒仅在应用前台打开时弹窗；套壳后接入 Capacitor 本地通知插件，
   支持后台 / 锁屏提醒，开关沿用全局设置与日程模块内的 `scheduleRemindEnabled`。
3. **APK 内备份落盘改造**：当前导出 / 导入用浏览器的下载 / 选文件，在 APK WebView 内需改用
   `@capacitor/filesystem` + `@capacitor/share`（导出）与文件选择插件（导入）。
4. **对接教务网站自动导入成绩**：成绩模块已预留固定格式 `campus-platform.scores.v1` 与 Provider 适配器
   接口（`Store.registerScoreProvider / importScores`，本版无界面入口）。对接具体学校教务系统时，
   新增一个 `{ id, name, fetch(params), parse(raw) }` 适配器（登录、验证码、跨域抓取通常需后端代理），
   再在界面加入口即可，录入与统计逻辑无需改动。
